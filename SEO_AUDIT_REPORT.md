# Bukan Pipe — Technical SEO Audit Report

**Site:** https://bukanpipe.com  
**Stack:** Next.js App Router, bilingual `/fa` + `/en`  
**Audit date:** 14 September 2026  
**Scope:** Codebase + live production HTTP/HTML (no code changes in this phase)

This document is **Phase 1**. It is an audit and a recommended implementation plan. **No production code has been changed.** Implementation starts only after approval.

**Stability rules respected in recommendations:** do not change existing public URLs; do not remove pages; do not redesign UI; do not break `/fa` and `/en`; do not make large architectural changes without a separate go-ahead.

---

## Executive summary

The new industrial site already has a strong SEO foundation: locale-prefixed canonicals, bidirectional `hreflang` (`fa` / `en` / `x-default` → FA) on equivalent pages, keyword-aware titles on core Persian commercial pages, Organization + ManufacturingBusiness JSON-LD, Product / Article / FAQ / BreadcrumbList on content documents, and a live sitemap of **94 unique production URLs** with **no duplicate `<loc>` values**.

Google brand visibility and crawl hygiene are **not** yet at the same standard. The highest-impact gaps are:

| Priority | Finding | Why it matters |
|---|---|---|
| **P0** | `/favicon.ico` and `/apple-touch-icon.png` **do not exist**. Middleware **307s** them to `/en/favicon.ico` → **404**. Live tab icon is a **placeholder square SVG**, not the official logo. | Google cannot show the Bukan Pipe mark next to the sitename. Browser tabs, bookmarks, and iOS home shortcuts also fail. |
| **P0** | `/fa/engineering`, `/fa/knowledge`, `/fa/tools`, `/fa/standards` (and EN twins) return **HTTP 200**, `index, follow`, title **“Bukan Pipe”**, canonical **`https://bukanpipe.com`**. Intended `redirect()` is prerendered as HTML, not a 308. | Duplicate/soft-homepage URLs. Crawl waste. Possible dilution of the real homepage. |
| **P1** | Apex `/` **307 → `/en`**. `hreflang` **x-default → `/fa`**. | Google’s unmatched-language signal and the first-hit URL disagree. |
| **P1** | `robots.txt` disallows `/projects` etc. **without locale prefix**. Real URLs are `/en/projects`, `/fa/projects`. | `robots.txt` does not block those pages. Meta `noindex` currently saves them. |
| **P1** | Organization JSON-LD has **no `sameAs`**, **no `contactPoint`**, **no description**, and `alternateName` is still Latin **“Bukan Pipe”** (not «بوکان پایپ»). | Weak Knowledge Panel / brand entity signals. |
| **P1** | Product schema has **no `category`**. Live Article schema has **no `publisher.logo`**. | Incomplete Rich Results eligibility. |
| **P2** | Certifications and several product families are **weak in header/footer**. `/solutions` and `/industries` overlap applications with thinner titles. | Internal PageRank does not match the intended IA. |
| **P2** | Four Persian technical articles have **no English equivalent** (no `hreflang` pair — correctly omitted). | EN visibility gap, not a hreflang bug. |
| **P2** | FA `/request-quote` title is **double-suffixed**: `استعلام قیمت \| بوکان پایپ \| Bukan Pipe`. | Unprofessional SERP title. |
| **P3** | Several OG images use **ChatGPT-dated filenames**. Gallery images inflate sitemap image tags. | Brand quality / sitemap weight; not a crawl blocker. |

**Do not implement yet.** The safe-fix list is in [Recommended implementation (awaiting approval)](#12-recommended-implementation-awaiting-approval).

## 3. Indexability audit

### 3.1 robots.txt (live)

```
User-Agent: *
Allow: /
Disallow: /design-system
Disallow: /projects
Disallow: /pricing
Disallow: /dealers
Disallow: /verify

Host: https://bukanpipe.com
Sitemap: https://bukanpipe.com/sitemap.xml
```

Indexing is **on** in production (`Allow: /` + sitemap). Good.

**Bug:** Disallow paths are **not locale-prefixed**. Google matches from the start of the path. `/projects` does **not** match `/en/projects` or `/fa/projects`. The same applies to design-system, pricing, dealers, verify.

**Mitigation already in place:** those pages emit `noindex, nofollow` via `NOINDEX_PATHS` (verified live on `/en/projects`: `robots=noindex, nofollow`). So they should not index, but they **remain crawlable** and `robots.txt` is misleading.

**Safe fix (after approval):** disallow `/fa/projects`, `/en/projects`, and the same pattern for the other four stubs — **or** rely only on meta noindex and stop listing ineffective rules. Do not disallow `/` or locale prefixes.

### 3.2 Canonical tags

| Page | Live canonical | Verdict |
|---|---|---|
| `/fa` | `https://bukanpipe.com/fa` | Correct |
| `/en` | `https://bukanpipe.com/en` | Correct |
| `/fa/products/pe100-pipe` | `https://bukanpipe.com/fa/products/pe100-pipe` | Correct |
| `/en/products/pe100-pipe` | matching EN URL | Correct |
| `/fa/certifications` | locale URL | Correct |
| `/fa/gallery` | locale URL | Correct |
| `/fa/engineering` | **`https://bukanpipe.com`** (apex home) | **Wrong** for a 200 URL |
| `/en/projects` | `/en/projects` + noindex | Acceptable for a stub |

`createPageMetadata()` sets `alternates.canonical` with `withLocale`. Locale layout also calls `createRootMetadata()`, whose canonical is apex `/`. Child `generateMetadata` overrides on real pages. **Redirect stubs have no `generateMetadata`**, so they inherit the **homepage canonical** while remaining **200 + indexable**.

### 3.3 noindex tags

| Surface | Behavior |
|---|---|
| `NOINDEX_PATHS` | `/projects`, `/pricing`, `/dealers`, `/verify`, `/design-system` → `index: false, follow: false` |
| `app/[locale]/not-found.tsx`, `app/not-found.tsx` | noindex |
| Published catalog + extras | `index, follow` when `allowIndexing` is true |
| Redirect stubs | **index, follow** (should be 308, not indexed documents) |

### 3.4 HTTP status codes (production)

| URL | Status | Notes |
|---|---|---|
| `/fa`, `/en` | 200 | Canonical homepages |
| `/sitemap.xml`, `/robots.txt`, `/icon.svg` | 200 | |
| `/` | **307** → `/en` | Cookie `NEXT_LOCALE` can send `/fa`; crawlers typically have no cookie |
| `www` | **308** → apex | Correct |
| Trailing slash (e.g. `/gas-pipe/`) | **308** → slashless, then legacy/locale | Two hops; both 308 is OK |
| `/gas-pipe` | **308** → `/fa/products/gas-pipe` | Legacy map **is enabled** in production |
| `/about_us` | **308** → `/fa/about` | Good equity transfer |
| `/articles` | **308** → `/fa/technical-center` | Good |
| `/fa/engineering` (and knowledge/tools/standards) | **200 HTML** | Should be **308** to the new hubs |
| `/favicon.ico` | **307** → `/en/favicon.ico` | Then **404** |
| `/apple-touch-icon.png` | **307** → `/en/apple-touch-icon.png` | Then missing |

`ENABLE_LEGACY_REDIRECTS` defaults to **false** in code, but production behavior shows the flag **is on**. Keep it on. Expanding the map is a separate, report-first change.

Next.js `redirect()` (used by stub pages) is a **temporary** redirect when it works, and currently **does not emit an HTTP redirect at all** because the routes are **prerendered** (`X-Nextjs-Prerender: 1`, `X-Matched-Path: /fa/engineering`).

### 3.5 Redirect architecture

```
www.bukanpipe.com  ──308──►  bukanpipe.com
bukanpipe.com/     ──307──►  /en   (or /fa if NEXT_LOCALE=fa)
bare legacy path   ──308──►  /fa{newPath}   when ENABLE_LEGACY_REDIRECTS=true
unprefixed path    ──307──►  /{defaultLocale}{path}   defaultLocale = en
```

Middleware correctly bypasses `/_next`, `/api`, `/icon.svg`, `/robots.txt`, `/sitemap.xml`, `/media/*`. It does **not** bypass `favicon.ico`, `apple-touch-icon.png`, or `manifest.webmanifest`.

**Do not change public destination URLs.** Recommended later: emit **308** from stub routes to existing hubs (`/technical-center`, `/calculator`, `/downloads`) using `next.config` redirects or `permanentRedirect()`, so the old paths **remain** as aliases.

### 3.6 Duplicate-content risks

1. **Stub 200s** with homepage canonical (highest).
2. **Apex `/` vs `/en` vs `/fa`:** `/` is not in the sitemap; it 307s. Acceptable if x-default and default landing are aligned (they are not — see §5).
3. **Topic overlap** among pillar + complete guide + “what is HDPE”.
4. **Solutions / industries / applications** — three indexable hubs with overlapping intent. Solutions/industries use **weak titles** (`راهکارها | Bukan Pipe`), so they are more likely to be thin duplicates than applications.
5. EN/FA pairs are **not** duplicates when `hreflang` is present (verified on home and PE100).

## 5. Bilingual SEO / hreflang

### 5.1 Implementation

`buildLanguageAlternates()` (`lib/i18n/locale-availability.ts`):

- Emits `en` and `fa` **only if the path exists in that locale**.
- Sets **`x-default` to FA** (`languages.fa ?? languages.en`).
- Tests expect x-default of `/products/gas-pipe` → `https://bukanpipe.com/fa/products/gas-pipe`.

**Live verified (home + PE100):**

```html
<link rel="alternate" hrefLang="en" href="https://bukanpipe.com/en" />
<link rel="alternate" hrefLang="fa" href="https://bukanpipe.com/fa" />
<link rel="alternate" hrefLang="x-default" href="https://bukanpipe.com/fa" />
```

PE100 likewise cross-references `/en/products/pe100-pipe` ↔ `/fa/products/pe100-pipe`, x-default FA. **Correct.**

FA-only articles correctly **omit** `hreflang` (a single-locale document must not invent an EN URL).

`extraStaticPaths` includes `/request-quote`, `/solutions`, `/industries`, `/gallery` so those pairs get hreflang even without content-catalog documents.

### 5.2 Conflicts

| Signal | Value | Issue |
|---|---|---|
| hreflang x-default | FA pages | Iran-primary brand — **strategically correct** |
| `defaultLocale` in `lib/i18n/config.ts` | **`en`** | Apex `/` 307s to **`/en`** for Googlebot |
| Cookie `NEXT_LOCALE` | fa/en | Users can land on FA; crawlers usually cannot |

**Recommendation (needs explicit approval — this is architectural):** either (a) keep x-default FA and change cookie-less `/` to **`/fa`**, or (b) keep `/` → `/en` and set x-default to EN. **Do not do (a) without approval.** It changes first-hit language for English-only crawlers and some users, but it matches the Persian brand and current x-default.

Until then, Google can see: sitemap + x-default prefer FA; the domain root prefers EN.

### 5.3 Pair completeness

Equivalent commercial/trust/product/application/lab hubs are bilingual. Gaps:

- 4 FA technical articles without EN twins (listed in §2.3).
- EN technical hub does not list those four FA-only slugs (correct).

No incorrect FA↔EN pairing was found on sampled live pages.

## 6. Phase 2 audit — Google brand visibility (favicons)

**Current production**

| Asset | Status |
|---|---|
| `app/icon.svg` | **Placeholder**: 32×32 dark rect + empty stroke square. Not the official logo. Live **200**. |
| `favicon.ico` | **Missing.** `/favicon.ico` → 307 `/en/favicon.ico` → **404**. |
| `favicon.svg` | Only the placeholder `icon.svg`. |
| `apple-touch-icon.png` | **Missing.** Same locale 307 trap. |
| Web app manifest / PWA icons | **Missing.** |
| `metadata.icons` in `createRootMetadata()` | **Not set.** |
| Official logo file | `/media/demo/logo.png` (1024×1024, used in header + Organization `logo`) |

Google Search sitelink/favicon rules (simplified): a crawlable, square icon, multiple of 48px, stable URL, allowed by robots, representing the brand. A hollow square SVG **will not** become the Bukan Pipe SERP mark.

**Required after approval (no URL changes to pages):**

1. Exclude `/favicon.ico`, `/apple-touch-icon.png`, `/icon.svg` (already), and optional `/manifest.webmanifest` from locale middleware.
2. Generate from the **official logo** (`/media/demo/logo.png` or a cleaner square export):
   - `public/favicon.ico` (multi-size 32/48/64)
   - `public/favicon.svg` (true logo, transparent)
   - `public/apple-touch-icon.png` (180×180 PNG)
   - optional 192 / 512 PNG for manifest (Android home shortcut)
3. Set in `createRootMetadata()`:

```ts
icons: {
  icon: [
    { url: "/favicon.ico" },
    { url: "/favicon.svg", type: "image/svg+xml" },
  ],
  shortcut: "/favicon.ico",
  apple: "/apple-touch-icon.png",
}
```

4. Keep using the same logo URL in Organization schema (or a dedicated `/icon-512.png` if we add one). Google Knowledge Panel logo ≠ SERP favicon, but both should be the official mark.

This does **not** redesign the UI. Header already uses the PNG logo.
